# Схема данных и соглашения

Основа — официальные [output structure](https://php.lobsterdata.com/info/DataStructure.php)
и [product information](https://lobsterdata.com/info/docs/legal/LOBSTER_productInformation.pdf).
Ниже также зафиксированы собственные правила загрузчика и отчёта LOB Lab.

## Строки и поля

CSV без заголовка: `message` имеет 6 столбцов; `orderbook` — `4 × L`, то есть
20 при `L=5`. Строка k стакана — состояние **после** события k; состояния до
первого события в этой паре файлов нет. Сопоставление строго по номеру строки.

| Message | Тип в Python | Единицы / смысл |
| --- | --- | --- |
| time_seconds | `Decimal` из исходного текста | Секунды от локальной полуночи биржи |
| event_type | `int` | Код события |
| order_id | `int` | Ссылка на заявку, не индекс строки |
| size | `int` | Акции |
| price | `int` | USD × 10 000; для типа 7 — служебный код |
| direction | `int` | +1 buy, −1 sell для лимитной заявки |

В стакане повторяются `ask_price_i, ask_size_i, bid_price_i, bid_size_i`.
Тип всех этих полей — `int`; первая пара цен — лучшие ask/bid.
Уровни означают занятые цены: шаг между соседними уровнями может различаться.
Для исполнения сторона относится к исполненной лимитной заявке;
инициатор сделки имеет противоположную сторону.

| Тип | Событие |
| --- | --- |
| 1 | Новая лимитная заявка |
| 2 | Частичная отмена |
| 3 | Полное удаление |
| 4 | Исполнение видимой заявки |
| 5 | Исполнение скрытой заявки |
| 6 | Cross trade, например аукционная сделка |
| 7 | Служебный индикатор остановки / возобновления |

Отсутствующий ask: **9999999999**, bid: **−9999999999**, объём: **0**.
Это заполнители, не цены сделок. Тип 7: `order_id=0`, `size=0`,
`direction=-1`; `price=-1/0/1` означает остановку / возобновление котирования /
возобновление торгов. Его стакан повторяет предыдущий.

## Собственные правила точности

Цены разбираются напрямую `int(token)` после проверки десятичной записи целого.
`100.0`, экспоненциальная запись, пробелы, пустое поле и NaN не приводятся к
числу автоматически. Цены не проходят через `float`; множитель 10 000 —
единица представления, а не утверждение о минимальном биржевом тике.
Python сохраняет целые произвольной точности; диапазоны типов C++ пока не выбраны.

Время разбирается `Decimal(token)` точно, даже если дробная часть длиннее
заявленных в документации 9 знаков. Исходный текст остаётся в `CSVRow.raw`.
`Message.time_ns` возвращает целое число наносекунд только при точной
представимости, иначе `None`; округления нет. Дробная часть длиннее 9 знаков
помечается `message.time_precision_gt_ns`, запись сохраняется в метриках.
В официальном образце такая одна строка: **67823**, 12 дробных знаков.

Дата задаётся источником; часовой пояс с CSV не приходит. Для этого образца
принята биржевая зона `America/New_York` (летом EDT), без перевода в UTC или
локальное время компьютера. Числа `34200000/57600000` в имени файла — границы
в **миллисекундах**, а не фактические min/max событий; сами CSV используют секунды.

## Контракт загрузчика

```python
from lob_lab import iter_pairs

for row in iter_pairs("message.csv", "orderbook.csv", levels=5):
    # row.line — исходная позиция, начиная с 1.
    # row.message / row.orderbook — CSVRow либо None для непарного хвоста.
    # CSVRow.raw, .errors, .value доступны и без фильтрации.
    if row.message is not None and row.message.value is not None:
        message = row.message.value
        assert isinstance(message.price, int)
```

Есть отдельные `iter_messages` и `iter_orderbooks` в `lob_lab.loader`.
Загрузка потоковая. В памяти держатся текущие записи; отчёт дополнительно
хранит счётчики и гистограмму уникальных спредов. Сортировки нет. При равном
времени сохраняется исходный порядок, номер строки служит порядковым ключом.

Одна физическая строка — одна запись. Пустая строка считается записью с неверным
числом столбцов; кавычки с переносом строки не поддерживаются. Ошибка CSV,
размерности или преобразования даёт `value=None` и `.errors`, но не удаляет
позицию и не сдвигает выравнивание. Все ошибки преобразования полей одной
строки проверяются; при неверной размерности содержимое не интерпретируется.
Нечитаемый файл или неверная кодировка останавливает команду с ошибкой.

## Проверки качества

Проверки не меняют исходники. Семантически подозрительные записи остаются
типизированными; синтаксически неразбираемые доступны как исходная строка.
Отчёт считает каждую причину один раз на позицию и показывает первые пять
номеров. `suspicious_rows` — объединение отмеченных позиций; суммы причин
могут превышать его. Отсутствующая причина имеет нулевой счётчик.

| Проверка | Причина в `issues` |
| --- | --- |
| Непарные хвосты; равенство числа строк | `pair.missing_message`, `pair.missing_orderbook`; `row_counts_match` |
| Размерность / синтаксис CSV | `message/orderbook.column_count`, `.csv_syntax` |
| Целые поля и десятичное время | `message/orderbook.integer_format`, `message.time_format` |
| Время вне суток, избыточная точность, убывание | `message.time_out_of_day`, `.time_precision_gt_ns`, `.time_decrease` |
| Неизвестный тип, отрицательный ID, сторона | `message.unknown_event_type`, `.negative_order_id`, `.invalid_direction` |
| Цена обычного события вне `(0, 9999999999)` | `message.invalid_price` |
| Отрицательный / нулевой размер обычного события | `message.negative_size`, `.zero_size` |
| Некорректные поля типа 7 / изменение его стакана | `message.invalid_halt_marker`, `orderbook.halt_state_changed` |
| Отрицательный объём по стороне | `orderbook.ask/bid.negative_size` |
| Нулевой объём без правильного заполнителя | `orderbook.ask/bid.zero_size_occupied` |
| Заполнитель с ненулевым объёмом | `orderbook.ask/bid.sentinel_nonzero_size` |
| Неправильная цена, в том числе заполнитель другой стороны | `orderbook.ask/bid.invalid_price` |
| Нарушение строго возрастающих ask / убывающих bid | `orderbook.ask/bid.level_order` |
| Обычный уровень после отсутствующего | `orderbook.ask/bid.occupied_after_missing` |
| Пустая сторона | `orderbook.empty_side` |
| Лучший ask равен bid / меньше bid | `orderbook.locked`, `orderbook.crossed` |
| Оба файла пусты | `dataset.empty` — один случай на набор, без номера строки |

Убывание времени проверяется между последовательными **разобранными message**;
неразбираемые строки имеют собственную причину. Связанные счётчики событий и
времени строятся по всем разобранным message, включая семантические замечания.
Равные времена допустимы и считаются в `observations.time_ties`.
Тип 6 не проверяется как сторона покоящейся заявки. Для типа 7 нулевой объём
допустим; для остальных типов нулевой объём отмечается. Нулевой ID не отвергается:
его уникальность между всеми типами событий здесь не предполагается.

Объём `0` с правильным заполнителем допустим и учитывается по ячейкам в
`ask/bid_missing_levels` и `ask/bid_zero_size_cells`. Строгий порядок цен
проверяется по значениям обычных уровней с пропуском правильных заполнителей.
Пустая сторона означает отсутствие среди L уровней хотя бы одной обычной
положительной цены с положительным объёмом. Отдельно считаются пустые ask/bid,
хотя бы одна пустая сторона и обе пустые стороны. Некорректный нулевой лучший
уровень при занятых дальних уровнях — ошибка объёма, но не полностью пустая сторона.

## Статистики отчёта

- Число физических строк обоих файлов, совпавших позиций и разобранных записей.
- Min/max и первое/последнее время точно; JSON хранит секунды строкой и
  min/max наносекунд целым либо `null`, если точное представление невозможно.
- Число событий каждого типа 1–7, включая нули; неизвестные типы идут отдельно.
  Сумма — число разобранных message, не обязательно всех физических строк.
- Спред `ask_price_1 − bid_price_1` в единицах 0,0001 USD, полная частотная
  гистограмма, min/max, среднее и p50/p95/p99 методом ближайшего ранга
  `ceil(p × N)`. Все цены/границы целые; только среднее — строка `Decimal`
  с текущей десятичной точностью Python (по умолчанию 28 значащих цифр).
- Изменения mid-price считаются сравнением целых **ask+bid**, без деления на 2.
  Это сохраняет изменения на половину единицы цены и не создаёт ошибок float.

Для спреда и mid нужны оба первых уровня с ценами в `(0, 9999999999)` и
положительными объёмами. Если они не подходят, строка явно входит в
`excluded_orderbook_rows`. Ошибки дальних уровней или message не исключают
корректные лучшие котировки. Locked/crossed входят в распределение как нулевые/
отрицательные спреды, одновременно получают замечание.

Сравнение mid строится только между соседними физическими строками стакана,
если обе пригодны. Через пустые/неразбираемые состояния сравнения не строятся;
`excluded_adjacent_pairs` показывает их число. Стакан без парного message
по-прежнему входит в статистики стакана и имеет `pair.missing_message`.
Повторы стакана и времени сохраняются. Все распределения взвешены **по строкам**,
не по длительности состояния; агрегации сделок и временного ресэмплинга нет.
